## Constraint Handling
To address the risk of underspecified relationship inference, the system enforces a strict heuristic: object properties (relationships) are only generated when a column name explicitly references another table's primary key (e.g., `table_id`). Ambiguous columns are treated as data properties. Null values are handled by inferring the range from non-null instances (type fallback). Column headers are normalized to camelCase to ensure valid OWL identifiers. No semantic inference is performed on cell content to prevent hallucination.
