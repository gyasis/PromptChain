## Method (cited)

We will implement a **stand‑alone Python script** that:

1. **Reads the CSV** line‑by‑line using `csv.DictReader` so we never load the whole file into memory.  
2. **Infers a column type** on the first *N* rows (default = 100) by trying `int → float → text`.  
   * This mirrors DuckDB’s `read_csv_auto` behaviour described in the DuckDB docs and the example in the corpus [1].  
3. **Creates a SQLite table** (`sqlite3` from the Python standard library) with the inferred column types.  
4. **Inserts rows** in batches (`executemany`) to keep I/O fast.  
5. **Verifies the import** by running `SELECT COUNT(*) FROM <table>` and returning the count.

**Why this approach?**  

* Pure‑Python → no external binary dependencies, works on any platform with a default Python install.  
* Incremental reading + batch inserts keep memory usage low, satisfying the “any sized CSV” requirement.  
* The type‑inference algorithm is deterministic and easy to test, while still providing the “basic” inference the brief asks for.  
* Using SQLite directly (instead of DuckDB → SQLite export) demonstrates the core logic without relying on a heavyweight DB engine.

**Citations**  

* DuckDB’s `read_csv_auto` example that performs automatic type inference and materialises a SQLite table [corpus] [1].  
* Python’s `csv` and `sqlite3` libraries are part of the standard library and are designed for exactly this kind of ETL task [Python Docs].
