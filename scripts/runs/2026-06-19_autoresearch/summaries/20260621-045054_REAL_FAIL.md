## Method (cited)  

1. **Load the CSV with pandas** – treat every column as a potential attribute.  
2. **Compute column cardinalities** (number of distinct values). Columns with low cardinality (relative to row count) are candidates for dimension keys; the column with the highest cardinality that is numeric or a timestamp is the primary measure for the fact table.  
3. **Detect functional dependencies** – for each pair *(candidate‑dim‑col → other‑col)* we test whether the values of *other‑col* are uniquely determined by *candidate‑dim‑col* (or by a small set of such columns). If a dependency holds, the determinant becomes the surrogate key of a dimension and the dependents become its attributes.  
4. **Group mutually dependent columns** – columns that are mutually functionally dependent form a single dimension (e.g., `product_id`, `product_name`, `product_category`).  
5. **Create dimension tables**  
   * Assign an auto‑increment surrogate key (`dim_<name>_id`).  
   * Populate with distinct rows of the grouped attributes.  
6. **Create the fact table**  
   * Use the surrogate keys of all discovered dimensions as foreign keys.  
   * Include the original numeric/measure columns (e.g., `quantity`, `sales_amount`).  
   * Add a surrogate fact key if desired (`fact_id`).  
7. **Export the schema** – write each table to a separate CSV (`dim_*.csv`, `fact.csv`) and emit a JSON manifest describing primary/foreign keys.  

The algorithm is implemented in a single Python module **`infer_star_schema.py`** (≈ 120 LOC) that follows the steps above and can be invoked from the command line:

