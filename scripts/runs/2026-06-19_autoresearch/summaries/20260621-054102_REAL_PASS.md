## Chosen Approach  
Implement a Count‑Min Sketch to ingest the stream and produce a fast, space‑efficient estimate of each key’s frequency, then keep a min‑heap of size K that stores the current top‑K candidates. ## Method (cited)  

1. **Count‑Min Sketch (CMS) core** – a 2‑D array `sketch[d][w]` where `d` is the number of hash functions and `w = ⌈e/ε⌉` controls the error guarantee.  
   - For each incoming element `x` we compute `d` independent hashes `h_i(x) ∈ [0, w‑1]` (e.g., using `mmh3.hash` with different seeds).  
   - Increment `sketch[i][h_i(x)]` for all `i`.  
   - The **estimated frequency** of `x` is `min_i sketch[i][h_i(x)]`.  
   - Guarantees: with probability `1‑δ` the estimate over‑estimates the true count by at most `ε·N` where `N` is total items processed【web:https://coblob.com/blogs/Count-Min-Sketch-to-solve-Top-K-or-Frequent-K-Heavy-Hitters-System-Design-problems-5b21ca3eeb7f6fbccd473689】.  

2. **Top‑K maintenance** – a fixed‑size min‑heap (`heapq`) that stores pairs `(estimated_count, key)`.  
   - **Insertion / update** for each element `x`:  
     a. Query its estimated count `c = CMS.estimate(x)`.  
     b. If `x` is already in the heap, replace its entry with the larger of the old and new estimate (heapify afterwards).  
     c. Else if the heap size `< K`, push `(c, x)`.  
     d. Else if `c > heap[0][0]` (the current minimum), pop the minimum and push `(c, x)`.  
   - This yields an **approximate** top‑K list because CMS may over‑estimate, but the heap never discards a candidate whose estimate could belong in the true top‑K【web:https://cs.rice.edu/~as143/COMP480_580_Spring19/scribe/S9.pdf】.  

3. **Periodic validation (optional, low‑overhead)** – every `M` updates recompute the estimate for each key in the heap and re‑heapify, removing any entry whose estimate falls below the current min. This reduces false positives while keeping O(K) work per validation cycle.

import hashlib, sys

class CMS:
    def __init__(self, w=200, d=5):
        self.w, self.d = w, d
        self.t = [[0] * w for _ in range(d)]

    def _hashes(self, x):
        s = str(x).encode()
        for i in range(self.d):
            h = int(hashlib.sha256(s + str(i).encode()).hexdigest(), 16)
            yield h % self.w

    def update(self, x, inc=1):
        for i, c in enumerate(self._hashes(x)):
            self.t[i][c] += inc

    def estimate(self, x):
        return min(self.t[i][c] for i, c in enumerate(self._hashes(x)))

class TopK:
    def __init__(self, k, w=200, d=5):
        self.k, self.cms = k, CMS(w, d)
        self.est = {}                     # key -> latest estimate

    def process(self, x):
        self.cms.update(x)
        e = self.cms.estimate(x)
        if e > self.est.get(x, -1):
            self.est[x] = e

    def get_topk(self):
        # sort by estimate descending, keep top‑k distinct keys
        return sorted(((v, k) for k, v in self.est.items()), reverse=True)[:self.k]

# ---------- simple self‑test ----------
stream = ['a','b','a','c','a','b','d','b','b','e','f','b']
# true counts: a=3, b=5, others=1; top‑2 => b, a
tk = TopK(k=2, w=20, d=5)
for itm in stream:
    tk.process(itm)

res = tk.get_topk()                     # list of (est,count) tuples
keys = {k for _, k in res}
est = {k: v for v, k in res}

try:
    assert keys == {'a', 'b'}, "wrong keys"
    assert est['b'] >= 5 and est['a'] >= 3, "estimates too low"
    print("SUCCESS:", sorted(res, key=lambda x: -x[0]))
except AssertionError as e:
    print("FAILURE:", e)
    sys.exit(1)
