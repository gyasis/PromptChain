## Chosen Approach  
Implement a Count‑Min Sketch (CMS) with *d* pairwise‑independent hash functions and a width *w* chosen so that the error guarantee \( \varepsilon \approx 2/w \) meets the desired precision. For every incoming stream element, update the *d* counters in the sketch (one per hash). Simultaneously maintain a size‑*K* min‑heap (or a bounded priority queue) of candidate heavy‑hitters; after each update compute the element’s estimated frequency as the minimum of its *d* CMS counters, and if this estimate exceeds the current heap minimum, insert or promote the element in the heap, evicting the smallest if necessary. At any point, the heap holds an approximate top‑K list with probabilistic error bounds inherited from the CMS. This combination yields O(1) update time, sub‑linear space, and a ready‑to‑report top‑K set.  

**Evidence**: Count‑Min Sketch can be used to solve top‑K heavy‑hitter problems by replacing a hashmap with the sketch and tracking candidate items [web:https://coblob.com/blogs/Count-Min-Sketch-to-solve-Top-K-or-Frequent-K-Heavy-Hitters-System-Design-problems-5b21ca3eeb7f6fbccd473689]; identifying top‑K from a CMS typically uses a min‑heap of size *K* to keep the largest estimated counts [web:https://cs.rice.edu/~as143/COMP480_580_Fall22/scribe/Lec9.pdf]; a real‑time leaderboard implementation follows exactly this pattern—CMS for compact frequency storage plus a bounded priority structure for emitting the current top‑K [web:https://medium.com/@ahzam.ali/designing-a-real-time-top-k-youtube-view-counter-from-5k-to-billion-of-events-c21b443493e7].

## Method (cited)  

1. **Count‑Min Sketch (CMS) construction** – Use a 2‑dimensional integer array of size `d × w` where `d` is the number of pairwise‑independent hash functions and `w = ⌈e/ε⌉` controls the additive error ε.  
   *Reference*: Coblob blog explains the CMS update rule and error bound【web:https://coblob.com/blogs/Count-Min-Sketch-to-solve-Top-K-or-Frequent-K-Heavy-Hitters-System-Design-problems-5b21ca3eeb7f6fbccd473689】.  

2. **Hash family** – For each row `i ∈ [0, d)` generate a hash `h_i(x) = (a_i * hash(x) + b_i) mod w` with random `a_i, b_i ∈ [1, w)`. The family is pairwise independent, satisfying the CMS analysis.  

3. **Update procedure** – For an incoming element `x`:  
   ```python
   for i in range(d):
       sketch[i][h_i(x)] += 1
   ```  

4. **Frequency estimate** – Query the sketch for an element `x` by returning the minimum counter across rows:  
   `freq̂(x) = min_i sketch[i][h_i(x)]`. This over‑estimates the true frequency but never under‑estimates (standard CMS guarantee).  

5. **Top‑K maintenance** – Keep a **size‑K min‑heap** of candidate heavy‑hitters (Python `heapq`). After each update:  
   * Compute `freq̂(x)`.  
   * If `x` is already in the heap, update its key (re‑heapify).  
   * Else if the heap has < K items, push `(freq̂(x), x)`.  
   * Else if `freq̂(x) > heap[0][0]` (the current K‑th highest estimate), pop the minimum and push the new candidate.  

   This yields **O(1)** amortised update time and **O(K)** space for the output list.  

6. **Reporting** – When the client requests the current top‑K, return the heap sorted descending by the stored estimate. The result is an *approximate* top‑K with the same ε‑error bound guaranteed by the underlying CMS.  

7. **Implementation details** –  
   * Python 3.9+ (standard library only).  
   * `random` for hash coefficients, `hashlib` as a stable base hash for non‑deterministic objects.  
   * Encapsulate the logic in a class `TopKHeavyHitters(k, eps=0.01, delta=1e-5)` exposing `update(item)` and `topk()` methods.  

All steps follow the textbook CMS algorithm and the min‑heap top‑K extraction pattern described in the Rice lecture notes【web:https://cs.rice.e

import hashlib, heapq

class TopK:
    def __init__(self,k,eps=0.2,delta=0.1):
        self.k=k
        self.w=int(2/eps)+1
        self.d=int(1/delta)+1
        self.sk=[[0]*self.w for _ in range(self.d)]
        self.A=[i+1 for i in range(self.d)]          # deterministic coeffs
        self.est={}                                   # item → current estimate

    def _h(self,x,i):
        h=int(hashlib.sha256(str(x).encode()).hexdigest(),16)
        return (self.A[i]*h)%self.w

    def _est(self,x):
        return min(self.sk[i][self._h(x,i)] for i in range(self.d))

    def update(self,x):
        for i in range(self.d):
            self.sk[i][self._h(x,i)]+=1
        self.est[x]=self._est(x)

    def topk(self):
        return sorted(self.est.items(),key=lambda kv:kv[1],reverse=True)[:self.k]

# ----- test -----
hh=TopK(k=3,eps=0.2,delta=0.1)
stream=['a','b','a','c','a','b','d','b','b','e']
for s in stream: hh.update(s)
res=hh.topk()
exp={'a', 'b', 'c'}                     # true top‑3 items

    print("FAILURE")
