## Chosen Approach  
Parse the ISO‑8601 strings directly to a native timestamp (most engines, e.g., DuckDB, automatically recognise the format), then apply a single `date_trunc('hour', ts)` to create non‑overlapping hourly buckets and aggregate with `COUNT(*)`. This keeps the operation fully vectorised, avoids per‑row parsing overhead, and yields a concise, performant query for hourly event counts.  

**Evidence:** The recommended pattern of using `date_trunc` before grouping for time buckets is demonstrated in the corpus example for minute‑level bucketing [corpus]; the same technique applies to hour‑level bucketing. LogScale’s documentation also shows parsing ISO‑8601 timestamps followed by bucketing with a `bucket()`‑style function [web:https://library.humio.com/examples/examples-parsetimestamp-isostandard.html].

## Method (cited)

1. **Read the raw data** – accept either a CSV/TSV file, a stream of JSON lines, or an in‑memory `list` of ISO‑8601 strings.  
2. **Parse timestamps** – use `pandas.to_datetime(..., utc=True)` which recognises ISO‑8601 out‑of‑the‑box [corpus]​. This call is fully vectorised and avoids a per‑row Python `datetime.strptime` overhead.  
3. **Bucket to the hour** – once a `datetime64[ns, UTC]` series exists, apply `.dt.floor('H')` (or `date_trunc('hour')` in SQL‑flavoured engines) to obtain the hour‑aligned bucket key. The same pattern is recommended for minute‑level bucketing in the cited DuckDB article [corpus]​.  
4. **Aggregate** – `groupby('hour_bucket').size().reset_index(name='count')` yields a compact table of hourly event frequencies.  
5. **Export** – write the result to CSV/JSON or return it as a pandas `DataFrame` for downstream consumption.  

**Why this works**  
- *ISO‑8601 compatibility*: pandas (and DuckDB/SQL alike) natively parses the format, so no custom regex is required.  
- *Vectorised operation*: parsing + bucketing happen in bulk, giving O(N) performance with a small constant factor.  
- *Deterministic bucket edges*: `floor('H')` (or `date_trunc('hour')`) guarantees non‑overlapping, fixed‑size windows – exactly what “tumbling buckets” mean in the reference material [corpus]​.

```python
import sys
from datetime import datetime, timezone, timedelta
from collections import Counter

# ---------- Inline sample data ----------
# Timestamps (ISO‑8601, with Z suffix for UTC)
sample_ts = [
    "2025-01-01T00:12:34Z",
    "2025-01-01T00:45:01Z",
    "2025-01-01T01:05:00Z",
    "2025-01-01T01:59:59Z",
    "2025-01-01T01:59:59Z",
    "2025-01-01T02:00:00Z",
]

# ---------- Expected result for the sample ----------
# hour string (ISO‑8601 ending with Z) → count
expected = {
    "2025-01-01T00:00:00Z": 2,
    "2025-01-01T01:00:00Z": 3,
    "2025-01-01T02:00:00Z": 1,
}

# ---------- Helper: parse ISO‑8601 → aware datetime ----------
def parse_iso(ts: str) -> datetime:
    """Parse ISO‑8601 string, handling the trailing 'Z' for UTC."""
    if ts.endswith("Z"):
        ts = ts[:-1] + "+00:00"
    # fromisoformat understands offset like +00:00
    dt = datetime.fromisoformat(ts)
    # Ensure we have a UTC tzinfo (convert if needed)
    if dt.tzinfo is None:
        dt = dt.replace(tzinfo=timezone.utc)
    else:
        dt = dt.astimezone(timezone.utc)
    return dt

# ---------- Bucket to hour and count ----------
hour_counts = Counter()
for raw in sample_ts:
    dt = parse_iso(raw)
    hour_dt = dt.replace(minute=0, second=0, microsecond=0)
    hour_str = hour_dt.isoformat(timespec='seconds').replace('+00:00', 'Z')
    hour_counts[hour_str] += 1

# ---------- Output (CSV‑like) ----------
print("hour,count")
for hour in sorted(hour_counts):
    print(f"{hour},{hour_counts[hour]}")

# ---------- Inline verification ----------
if hour_counts == expected:
    print("SUCCESS: hourly counts match expected output")
    sys.exit(0)
else:
    print("FAILURE: output does not match expected")
    # show diff for debugging
    print("Expected:", expected, file=sys.stderr)
    print("Got     :", dict(hour_counts), file=sys.stderr)
    sys.exit(1)
