## Method (cited)

We will pre‑train a 70 B‑parameter decoder‑only transformer on an 8‑node A100‑40 GB cluster (64 GPUs total) using a **hybrid tensor‑parallel + pipeline‑parallel** scheme that is proven to scale large language models:

| Component | Library / Technique | Reason |
|-----------|--------------------|--------|
| **Tensor‑parallelism** | Megatron‑LM [1] | Splits each transformer layer across GPUs, keeping per‑GPU activation memory < 40 GB. |
| **Pipeline‑parallelism** | DeepSpeed‑ZeRO‑3 + pipeline parallelism [2] | Enables model‑parallel stages across nodes, sharding optimizer / gradient states so the full 70 B model fits in aggregate GPU memory. |
| **Mixed‑precision** | BF16 (NCCL) [3] | Doubles throughput on A100 hardware while preserving numerical stability. |
| **Activation checkpointing** | PyTorch `torch.utils.checkpoint` [4] | Reduces activation memory at ~10 % extra compute. |
| **Distributed launch** | `torch.distributed.run` (NCCL backend) [5] | Handles multi‑node communication with minimal boiler‑plate. |
| **Data pipeline** | `datasets` streaming + `torch.utils.data.DataLoader` with sharding [6] | Guarantees each GPU sees a unique slice of the massive text corpus without pre‑loading everything into memory. |
| **Post‑training validation** | One‑shot inference via the **House‑GPU** endpoint (`http://house-gpu.local:8773/v1`) [7] | Confirms the checkpoint produces sensible logits before full fine‑tuning. |

**Citations**
